\begin{abstract}
This document describes how a partner router connects to the current
\code{lunarbase-contracts} deployment, how to obtain bit-exact off-chain
quotes through \code{lunarbase-sdk}, and how the integration differs from
v1 in \code{dark_pools/contracts}. It is intended for engineers integrating
LunarBase into an existing Solidity, Rust, or TypeScript system.
\end{abstract}

\textbf{Pinned revisions:}
\begin{itemize}
  \item SDK: \code{981595c8f290d38f411c36df44020e313206abca};
  \item current contracts: \code{61560730ba6051fa344c48dd6323b2b4cfe5f10f};
  \item legacy v1: \code{1082c95256328d0a0df79b3dc7cbe4873212b8e1}.
\end{itemize}

\textbf{Scope.} This is a short quote and swap integration specification. It
does not describe deployment ceremonies or capital management. The Core
address, chain ID, implementation address, and implementation code hash must
come from an approved deployment manifest rather than from example values in
this document.

\section{Target model}

A current deployment exposes one \code{CoreUUPS} proxy. Core has one immutable
CASH asset, while every other supported asset is represented by a lane to
CASH:

\begin{center}
\code{realtime stream -> ordered reducer -> in-memory state -> quote/quoteMany}
\end{center}

\begin{itemize}
  \item \code{asset <-> CASH} uses one lane;
  \item \code{assetA <-> assetB} routes through CASH automatically;
  \item one Core serves multiple lanes and many pairs;
  \item on-chain quotes and swaps depend on \code{msg.sender}, the router;
  \item one SDK client tracks one Core and one configured router;
  \item the SDK quote path is synchronous and performs no RPC, Redis access,
        or full-state clone.
\end{itemize}

The public on-chain entry points are:

\begin{lstlisting}[language=Solidity]
quoteExactIn(uint256 amountIn, address assetIn, address assetOut)
    returns (uint256 amountOut);

quoteExactOut(address assetIn, uint256 amountOut, address assetOut)
    returns (uint256 amountIn);

swapExactIn(ExactInputParams params) returns (uint256 amountOut);
swapExactOut(ExactOutputParams params) returns (uint256 amountIn);
\end{lstlisting}

The Solidity source uses the user-defined \code{Asset} type. Its ABI
representation is a regular \code{address}.

\subsection{Price, fees, and availability}

A lane stores the CASH price of one asset, not a square-root price:

\begin{center}
\code{price = CASH / asset}, \qquad
\code{scale = 10^(cashDecimals - assetDecimals) * 1e18}.
\end{center}

Token amounts are always raw integers. Monetary values must not be converted
to JavaScript \code{number} or any other floating-point representation.

A lane is available only when it exists, is not paused, and
\[
  executionBlockNumber \le latestUpdateBlock + blockDelay.
\]
Both lanes must be available for a routed quote. An insufficient liquidity
basis, zero anchor, spread exhaustion, or insufficient output reserve also
makes a quote unavailable.

The on-chain exact-input quote returns \code{0} when unavailable. Exact-output
returns \code{type(uint256).max}, except for the separate zero-request case.
The SDK exposes a typed \code{UnavailableReason} instead of these sentinels.

The protocol BPS denominator is $1{,}000{,}000$, so $10{,}000$ means $1\%$.
A complete off-chain quote contains \code{amountIn}, \code{amountOut},
\code{feeAsset}, \code{feeAmount}, \code{partnerFee}, and
\code{treasuryFee}.

\section{On-chain router integration}

\subsection{Router identity is part of the quote}

Core uses \code{msg.sender} for all of the following:
\begin{itemize}
  \item whitelist status and the blacklist fee multiplier;
  \item partner fee configuration;
  \item input-asset collection during a regular swap;
  \item partner-fee attribution.
\end{itemize}

\risk{The router configured in the SDK or indexer must be the same address as
\code{msg.sender} of the future on-chain swap.} A quote for an EOA may differ
from a swap executed by an adapter contract. A control \code{eth_call} must
also set its \code{from} field to the real router address.

\subsection{Minimal Solidity adapter}

The example uses OpenZeppelin \code{SafeERC20}. The adapter first receives the
user's tokens; Core then pulls the input from the adapter. A production
adapter must define its own access-control, refund, and slippage policies.

\begin{lstlisting}[language=Solidity]
// SPDX-License-Identifier: MIT
pragma solidity 0.8.35;

import {IERC20} from
    "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {SafeERC20} from
    "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";

struct ExactInputParams {
    address assetIn;
    address assetOut;
    address recipient;
    uint256 amountIn;
    uint256 amountOutMinimum;
    uint256 deadline;
}

interface ILunarBaseCore {
    function quoteExactIn(
        uint256 amountIn,
        address assetIn,
        address assetOut
    ) external view returns (uint256 amountOut);

    function swapExactIn(ExactInputParams calldata params)
        external payable returns (uint256 amountOut);
}

contract LunarBaseAdapter {
    using SafeERC20 for IERC20;

    address internal constant NATIVE =
        0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE;

    ILunarBaseCore public immutable core;

    constructor(ILunarBaseCore core_) {
        core = core_;
    }

    // Core observes this adapter as msg.sender.
    function quoteExactIn(
        address assetIn,
        address assetOut,
        uint256 amountIn
    ) external view returns (uint256) {
        return core.quoteExactIn(amountIn, assetIn, assetOut);
    }

    function swapExactIn(
        address assetIn,
        address assetOut,
        address recipient,
        uint256 amountIn,
        uint256 minimumOut,
        uint256 deadline
    ) external payable returns (uint256 amountOut) {
        uint256 nativeValue;
        if (assetIn == NATIVE) {
            require(msg.value == amountIn, "native value");
            nativeValue = amountIn;
        } else {
            require(msg.value == 0, "unexpected value");
            IERC20 token = IERC20(assetIn);
            token.safeTransferFrom(msg.sender, address(this), amountIn);
            token.forceApprove(address(core), amountIn);
        }

        amountOut = core.swapExactIn{value: nativeValue}(
            ExactInputParams({
                assetIn: assetIn,
                assetOut: assetOut,
                recipient: recipient,
                amountIn: amountIn,
                amountOutMinimum: minimumOut,
                deadline: deadline
            })
        );
    }
}
\end{lstlisting}

Before submitting a swap, the integrator applies its own tolerance to a fresh
off-chain \code{amountOut} and passes the result as
\code{amountOutMinimum}. The integrator also owns the deadline policy.
Exact-output follows the same pattern with \code{amountInMaximum}.

\subsection{ERC-20, native asset, and Permit2}

\begin{itemize}
  \item ERC-20: Core pulls \code{amountIn} from \code{msg.sender}; the router
        must own the token and approve Core.
  \item The current native-asset sentinel is
        \code{0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE}; the router forwards
        the exact \code{msg.value}.
  \item The Permit2 overload passes \code{msg.sender} to Permit2 as the owner.
        A contract router therefore cannot forward an end-user signature as
        if the user were the owner. Either the EOA calls Core directly, or the
        router first receives the input token and uses the regular swap flow.
\end{itemize}

\section{Off-chain connection}

\subsection{Required deployment identity}

Each active client instance is configured with:
\begin{itemize}
  \item network, chain ID, and Core proxy address;
  \item one router and its expected whitelist status;
  \item deployment block or an explicit list of lane assets;
  \item ERC-1967 implementation and its runtime-code Keccak-256 hash;
  \item the exact \code{MATH_COMPATIBILITY_VERSION};
  \item HTTP RPC and realtime WebSocket endpoints in the concrete data source.
\end{itemize}

The client becomes ready only after bootstrap and code-hash verification. A
gap, reorg, removed log, incompatible upgrade, or bounded-queue overflow must
disable quoting until canonical recovery succeeds.

\subsection{Ready-to-run HTTP indexer}

A minimal production-shaped invocation is:

\begin{lstlisting}[language=bash]
cargo run -p lunarbase-indexer \
  --no-default-features --features base \
  -- --network base \
     --chain-id 8453 \
     --core 0x1111111111111111111111111111111111111111 \
     --router 0x2222222222222222222222222222222222222222 \
     --expected-implementation 0x3333333333333333333333333333333333333333 \
     --expected-implementation-code-hash 0x4444444444444444444444444444444444444444444444444444444444444444 \
     --http-rpc-url https://rpc.example \
     --realtime-url wss://rpc.example

curl --fail-with-body http://127.0.0.1:8080/readyz

curl --fail-with-body \
  -H 'content-type: application/json' \
  -d '{
    "assetIn":  "0x1111111111111111111111111111111111111111",
    "assetOut": "0x2222222222222222222222222222222222222222",
    "amount": "1000000",
    "mode": "ExactIn"
  }' \
  http://127.0.0.1:8080/v1/quote
\end{lstlisting}

Amounts are decimal strings. A response is bound to a \code{cursor},
\code{executionBlockNumber}, implementation code hash, and math version.
\code{POST /v1/quotes} accepts up to 256 requests and evaluates the entire
batch on one state snapshot.

\subsection{Embeddable TypeScript}

Until package publication, all packages should be pinned to one approved Git
revision. The complete bootstrap identity flow is available in
\code{examples/typescript/quote-logger}.

\begin{lstlisting}[language=TypeScript]
import { connect, quoteCriticalTopics } from "@lunarbase/client";
import { createBaseFlashblocksSource } from
  "@lunarbase/source-evm";

const source = createBaseFlashblocksSource({
  httpRpcUrl: process.env.RPC_URL!,
  realtimeUrl: process.env.WS_URL!,
  chainId: 8453n,
});

const client = await connect({
  deployment, // verified Core/router/implementation identity
  filter: {
    address: deployment.core,
    topics: quoteCriticalTopics(),
  },
  queueBound: 4096,
  reconnectDelayMilliseconds: 1_000,
  sourceStallTimeoutMilliseconds: 30_000,
}, source);

const quote = client.quote({
  assetIn,
  assetOut,
  amount: 1_000_000n,
  mode: "ExactIn",
});

if (quote.outcome.kind !== "Available") {
  throw new Error(quote.outcome.reason.kind);
}
console.log(quote.cursor, quote.outcome.result.amountOut);
await client.shutdown();
\end{lstlisting}

The runnable example requires:

\begin{lstlisting}[language=bash]
RPC_URL=https://...
WS_URL=wss://...
CORE_ADDRESS=0x...
ROUTER_ADDRESS=0x...
EXPECT_WHITELISTED=true

make quote-logger-ts
\end{lstlisting}

\subsection{Embeddable Rust}

Rust uses the same concepts and ordered reducer:

\begin{lstlisting}[language=Rust]
use lunarbase_client::prelude::{
    Commitment, ConnectedQuoteClient,
};
use lunarbase_math::prelude::{QuoteMode, QuoteRequest, U256};

let client =
    ConnectedQuoteClient::connect(config, source, None).await?;
client.await_ready(Commitment::Realtime).await?;

let quote = client.quote(&QuoteRequest {
    asset_in,
    asset_out,
    amount: U256::from(1_000_000_u64),
    mode: QuoteMode::ExactIn,
})?;

println!("{:?} @ {:?}", quote.outcome, quote.cursor);
client.shutdown().await;
\end{lstlisting}

The full Base bootstrap, including ERC-1967 implementation and code-hash
reads, is in \code{examples/rust/quote-logger}. Run it with
\code{make quote-logger-rust}.

\section{Realtime state required at the integration boundary}

The client must not derive reserve state from \code{SwapExecuted}. After
settlement, Core performs reserve synchronization; canonical \code{Sync}
contains the post-state reserve. The quote and swap integration boundary
observes:

\begin{itemize}
  \item \code{LaneAdded}, \code{LaneRemoved}, and \code{LaneUpdated};
  \item \code{LanePausedSet}, \code{PricePushThresholdSet},
        \code{SlippageKSet}, and \code{BlockDelaySet};
  \item \code{Sync} for lane reserve and CASH reserve;
  \item \code{PartnerInfoSet}, \code{PartnerFeeSet}, \code{WhitelistSet},
        and \code{BlacklistFeeMultiplierSet};
  \item ERC-1967 \code{Upgraded}.
\end{itemize}

\code{LaneUpdated} replaces the complete packed \code{slot0}; a reducer must
not patch only price and fee fields. The subscription is opened before the RPC
snapshot, and events received during snapshot construction are replayed in
canonical order. The list above intentionally does not describe the complete
internal SDK state schema.

  (\texorpdfstring{\code{dark_pools/contracts}}{dark-pools/contracts})}

Deployment &
One UUPS \code{Pool} per X/Y pair; X and Y are immutable. &
One UUPS \code{Core} per deployment, with one CASH asset and many lanes. \\

Routing &
Only the two assets of a specific Pool. Multiple pairs require an external
router and multiple Pools. &
A direct lane to CASH or an internal
\code{assetIn -> CASH -> assetOut} route. \\

Math &
Reserve-sensitive PMM with Q64.96 square-root price, Q24 fees, and Q20.12
\code{concentrationK}; directional quotes also return \code{pNext}. &
Linear anchor conversion at the CASH/asset price, fees, and liquidity-based
slippage. Reserve is a solvency and output-availability bound. \\

Reserves &
\code{reserveX/reserveY} directly affect PMM output and change after every
swap. &
\code{assetReserve/cashReserve} limit execution; slippage uses
\code{totalPrincipalAmount}. \\

Modes &
Exact-input only, including directional
\code{quoteXToY/quoteYToX}. &
Exact-input and exact-output, both direct and routed. \\

Price update &
\code{upd(uint160,uint24,uint24)} updates one Pool's square-root price and
fees. &
Batch \code{update_0x3260a5e6(UpdateCalldata[])} updates multiple packed
lanes. A strict threshold excess retains the update and pauses the lane. \\

Pause &
One global pause for the entire Pool. &
Global Core swap pause plus an independent pause for every lane. \\

TTL boundary &
Fresh only while
\code{block.number < latestUpdateBlock + blockDelay}; the boundary is stale. &
Valid while
\code{executionBlockNumber <= latestUpdateBlock + blockDelay}; TTL is
inclusive. \\

Native asset &
\code{address(0)} and a dedicated \code{swapExactInNative}. &
\code{0xEeee...EEeE} and shared payable exact-input/exact-output entry points. \\

Partner profile &
Per Pool: \code{partnerInfo[router]}, with cumulative fees in both X and Y. &
Per Core: \code{partners[router][asset]}, with fee accounting and withdrawal
per asset. \\

Blacklist multiplier &
A stored zero is effectively interpreted as multiplier $1$. &
For a non-whitelisted router, multiplier zero produces zero effective lane
fee and must be indexed exactly. \\

Quote-state events &
\code{StateUpdated}, \code{Sync}, \code{ConcentrationKSet},
\code{BlockDelaySet}, whitelist/multiplier, and partner events. &
Lane, control, reserve, partner, and ERC-1967 upgrade events. \\

SDK compatibility &
Requires separate v1 PMM math and reducer; current
\code{lunarbase-math 0.3.x} is not compatible. &
Supported by the current Rust and TypeScript math, client, and network-source
packages. \\

\section{Migration checklist from v1 to Core}

\begin{enumerate}
  \item Replace each Pool address with one Core proxy and verify the ERC-1967
        implementation and code hash.
  \item Map X/Y pairs to CASH and lane assets. Remove the assumption that one
        contract address represents one pair.
  \item Convert the price feed from Q64.96 square-root price to the documented
        CASH/asset uint112 scale, and convert Q24 fees to protocol BPS.
  \item Replace PMM reserve math with the pinned \code{lunarbase-math}. Do not
        reuse v1 \code{pNext} or \code{concentrationK}.
  \item Account for inclusive TTL and separate global and per-lane pause state.
  \item Replace native sentinel \code{address(0)} with
        \code{0xEeee...EEeE}.
  \item Pin one router profile per client instance and verify its whitelist,
        multiplier, and partner fee for each fee asset.
  \item Move the indexer to the new events and use \code{Sync} for post-swap
        reserve state. Other quote-critical liquidity inputs remain outside
        this specification.
  \item Use \code{quoteMany} for batch routing rather than sequential RPC
        \code{eth_call} requests on the hot path.
  \item Before enabling traffic, compare SDK and on-chain quotes with the same
        \code{from/router}, block, and input corpus.
\end{enumerate}

\section{Integration invariants}

An integration is correct only when all of the following hold:
\begin{itemize}
  \item \ok{identity}: chain, Core, router, implementation, code hash, and math
        version match the deployment manifest;
  \item \ok{state}: quotes are served only by a ready client and include a
        cursor;
  \item \ok{parity}: router and execution block match the on-chain context;
  \item \ok{execution}: the caller defines \code{amountOutMinimum} or
        \code{amountInMaximum}, as well as the deadline;
  \item \ok{failure}: gaps, reorgs, upgrades, and queue overflow fail closed
        instead of serving uncertain state;
  \item \ok{amounts}: all token amounts remain raw integers.
\end{itemize}
